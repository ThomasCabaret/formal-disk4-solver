# Problem specification — SPEC-001

Version 1, 2026-10-21. This is a working research contract, not a new theorem or
a completeness claim about the software. Its [study record](studies/SPEC-001-problem-domain.md)
records the evidence and decisions. Mathematical claims newly derived here
remain subject to independent review.

## 1. Broad target

Normalize the target to the closed disk

\[
D=\{x\in\mathbb R^2:\|x\|^2\leq1\},\qquad O=(0,0).
\]

For a specified integer \(n\geq2\), seek a compact Jordan region \(T\)
(homeomorphic to a closed disk) and Euclidean isometries

\[
g_i(x)=Q_i x+t_i,\quad Q_i^TQ_i=I,\quad T_i=g_i(T),
\]

such that

\[
\bigcup_{i=1}^nT_i=D,
\qquad \operatorname{int}(T_i)\cap\operatorname{int}(T_j)=\varnothing
\quad(i\ne j).
\]

Reflections are allowed by default: \(\det Q_i\in\{-1,1\}\). A direct-only
variant explicitly requires \(\det Q_i=1\). Tiles may be nonconvex. The base
question assumes no differentiability, rectifiability, global symmetry,
intrinsic tile symmetry, connected pairwise intersection, prescribed contact
graph, minimum graph degree or unique embedding.

The finite-contact, piecewise-regular cases used by algorithms are named
subclasses. A finite cell complex is not assumed to represent every possible
Jordan-boundary tiling.

### Operational meaning of nontriviality

Keep two distinct predicates:

\[
\mathrm{NT}_{center}:\quad \exists i\; O\notin T_i,
\qquad
\mathrm{STEIN}:\quad \exists c\;O\in\operatorname{int}(T_c).
\]

`NT_center` is the default discovery predicate for this programme, reflecting
the earlier interest in the known 12-tile examples. `STEIN` is a stronger
separate target. For \(n>1\), `STEIN` implies `NT_center`: if a different
Jordan tile contained \(O\), its interior would accumulate at \(O\), inside
the open neighbourhood already occupied by the center tile. This contradicts
disjoint interiors. The converse is not assumed.

For provenance, [Kurusa, Lángi and Vígh, v1, introduction, Questions 1–2 and
Figure 2](https://arxiv.org/html/1910.03836) distinguish these two questions and
exhibit 12-tile examples for the first. Their Theorem 1.1 classifies disk
tilings with at most three Jordan tiles as rotationally generated. These are
reported source results; this study does not redo their proofs or establish
the present literature frontier.

An alternative request such as “not generated by rotations” must have its own
predicate. `NT_center` does not claim to classify all interesting tilings.
The dashboard's pizza/ring categories are display metadata, not definitions
of either predicate above. An abstract cycle alone does not determine which
tiles contain the physical center.

Weak nontrivial existence is already answered by known examples. Progress for
`R0` may therefore mean a new inequivalent construction, a new tile count or
family, an advance on Stein, a structural theorem, or a useful search method.
It cannot mean proving that all `NT_center` tilings are impossible.

## 2. Required study parameters

| Parameter | Broad default | Restriction that must be stated |
| --- | --- | --- |
| Target region | Complete Euclidean disk | Fixed other region, free patch, crown or fragment |
| Tile topology | Compact Jordan region | More general disconnected/holed tiles are outside this contract |
| Boundary | Arbitrary Jordan curve | Finite contacts, rectifiable, piecewise C2, circular/polynomial model |
| Congruence | All Euclidean isometries | Direct-only copies or a prescribed reflection pattern |
| Tile count | One declared count or explicit set | A finite upper bound is a domain restriction |
| Contacts | Not assumed connected or finite in number | Connected interfaces, finite cell complex, edge-to-edge, point restrictions |
| Embedding | Not prescribed | An embedded complex or a graph plus enumerated embeddings |
| Symmetry | None required | A specified geometric action, possibly of a chosen order |
| Tile symmetry | None required | A separate invariance constraint on the prototype |
| Success predicate | `NT_center` | `STEIN`, construction class, or an explicitly different predicate |

For a piecewise-regular model, a positive-length contact is a boundary
intersection with positive one-dimensional length. Point contacts must also
be recorded when they affect cyclic order or junctions. Outside that model,
positive arclength is not silently used as a universal contact definition.

A contact graph records adjacency; it loses contact multiplicities, point
junctions, contour order and embedding. An embedded cell complex retains
those data. An abstract automorphism of either object does not assert an
actual Euclidean rotation. Conversely, choosing no imposed symmetry permits
solutions that happen to be symmetric; it does not require asymmetric ones.

A free patch replaces disk equality by an explicitly chosen connected union
with unconstrained outer boundary; whether that union must be a Jordan region
is another declared condition. A partial disk patch retains the selected
circle contacts. Neither variant asserts extendability to a complete disk.
Any retained invariant about a completion must be necessary for that exact
completion problem and recognizable from the partial state.

## 3. Three finite computational variants

“Finite description” does not mean a finite set of real-valued candidates.
Fixing a graph or a tile count does not bound the number of word refinements
or the complexity of the prototype boundary.

### F1 — Bounded formal feasibility

Input: a finite embedded contact complex; boundary and symmetry data; a
prototype terminal-alphabet bound \(a\); a total expanded contour-word bound
\(L\); and an explicit finite set of rational affine length/angle/turn rules.
Copy parity, cut order and interval identifications are decisions unless fixed
by the request. All repeat exponents and derived cuts count toward \(L\).
All active terminal curves are non-erasing.

Question: is there an admissible assignment of finite words, endpoint orders,
positive lengths and angle/turn variables satisfying those rules?

This defined variant can be decided by finite enumeration of the discrete
objects followed by exact linear feasibility. Bounds \(a,L\) are logical
domain bounds, not wall-clock budgets. The statement applies to the declared
affine subsystem; additional nonlinear conditions require a different oracle.

An exact YES supplies a formal witness. It still needs geometric realization.
An exact NO excludes only that complex, the specified bounds and constraints.
Transferring NO to geometric tilings additionally requires proof that every
geometric solution in scope induces one of the enumerated formal witnesses.
The existing word solver's supported families are not automatically an
implementation of this fully bounded, exhaustive variant.

### F2 — Exact placement or synthesis in a semialgebraic template

Input: \(n\) and a finite membership formula \(\phi_\theta(x)\) using
polynomials with rational/algebraic coefficients, plus an admissibility formula
\(A(\theta)\). A template must come with a proof or independent check that
every admissible \(T_\theta=\{x:\phi_\theta(x)\}\) is a compact Jordan
region. That topology obligation is part of the input contract, not something
polynomial inequalities guarantee automatically. Fixing \(\theta\) gives
the known-prototype placement variant; existential \(\theta\) gives synthesis.

Define membership in placed copy \(i\) by

\[
M_i(x)=\phi_\theta\bigl(Q_i^T(x-t_i)\bigr).
\]

Interior membership has a first-order definition

\[
I_i(x)\iff\exists r>0\;\forall y\;
  (\|y-x\|^2<r^2\Rightarrow M_i(y)).
\]

The complete assembly constraints are

\[
\forall x\;[(\|x\|^2\leq1)\iff\bigvee_i M_i(x)],
\qquad
\forall x\;\bigwedge_{i<j}\neg(I_i(x)\land I_j(x)).
\]

Together with \(A\), orthogonality and the chosen center predicate, these
give a finite first-order formula over the reals. `NT_center` becomes
\(\bigvee_i\neg M_i(O)\); `STEIN` becomes \(\bigvee_i I_i(O)\).
Coverage and containment are both in the biconditional. Boundary sharing is
allowed by using interiors in the overlap condition.

Effective real quantifier elimination decides such formulas in principle;
see [Basu's survey, sections 1.2 and 2.1](https://www.math.purdue.edu/~sbasu/raag_survey2011_final-sep4-2014.pdf).
This is a specification route, not an implemented solver or a practical runtime
claim. Its reduction here is subject to independent review. Finite topology
or symmetry choices may be added by explicit formulas or a finite outer
disjunction only after their semantics are encoded correctly.

A template using only finite straight-sided polygons cannot tile an exact
disk: the boundary of a finite union is contained in finitely many line
segments, which cannot contain the full circle. Circular/curved descriptions
are therefore essential for disk controls. This elementary observation also
explains why square and hexagon patch controls test a different boundary model.
Piecewise polynomial *parametrizations* alone do not provide exact circular
arcs; rational parametrizations or implicit circle predicates can do so.

F2 does not cover arbitrary Jordan tiles without an additional representation
theorem. No NP, PSPACE, hardness or existential-theory-of-reals classification
is claimed: this formulation has universal quantifiers, and input encoding,
degree and coefficient size matter.

### F3 — Bounded numerical realization

Input: a finite formal profile or shape template, bounds on curve resolution
and parameters, explicit assembly predicates and numerical tolerances. A finite
run additionally declares restarts, evaluations and/or a time budget.

Success levels must be separate: a realized single contour; an assembled
congruent patch; a numerically validated complete disk; an exact certified
witness. Record which predicates were checked at each level. A numerical
failure is unresolved even if every planned restart was attempted. Increasing
resolution explores another family; it does not certify exhaustion of all
shapes. Progressive 3/6/12-point geometry is a strategy inside F3.

## 4. Implementation comparison at revision 3b196e3

These are read-only observations, not new bug diagnoses or proof audits.

| Observed implementation | Consequence for interpretation |
| --- | --- |
| [`validate_dual_graph`](../../src/formal_disk4/graph_lab/space.py) accepts only simple, planar, 3-connected augmented graphs with at least three tiles | This is a representation restriction. Three-connectivity is useful for unique embedding, but no completeness theorem for `NT_center` is supplied. |
| [`PlanarMap`](../../src/formal_disk4/maps/base.py) stores finite vertices, contour cycles, interfaces and optional actions; `ProblemHypotheses` defaults to piecewise C2 | This represents a finite, regular subclass; it cannot silently inherit the unrestricted Jordan domain. |
| [`GraphLabSearchRequest`](../../src/formal_disk4/graph_lab/search_request.py) separates boundary/region/policy choices but couples several symmetry and crown options | Some mathematically meaningful combinations are not exposed by this interface. An unsupported combination is not an impossibility result. |
| [`ContactArrangementEnumerator`](../../src/formal_disk4/search/placement_adapter.py) and its evaluator reject unsupported imposed actions/prototype rotation | Contact V2 coverage must be stated per engine. |
| The word solver leaves specified residual systems unsupported; Contact V2 has no demonstrated finite closure for arbitrary derived cuts | Fixed graph plus completed direct-incidence traversal does not give unrestricted geometric exhaustion. |
| [`NumericalContourSolver`](../../src/formal_disk4/geometry/solver.py) realizes one contour, with placements derived elsewhere from the formal correspondences | The realization must fulfill the formal gluing contract. A concrete inconsistency would require auditing that chain; this does not imply a separate placement-search project. |

The 3-connectivity restriction is not necessary for *all* monohedral disk
tilings: two half-disks give a valid tiling whose augmented simple contact
graph is a triangle. This example has all tiles containing the center; it does
not demonstrate an omitted `NT_center` witness. The latter coverage question
remains open in this audit. Minimum degree three and three-connectivity must
also not be treated as equivalent graph conditions.

## 5. Certificate and comparison contract

Every negative report must identify the complex/generator, reflection and
symmetry restrictions, formal alphabet/cut/word bounds, supported word language,
geometric family, exact rejection evidence, and interrupted/unsupported cases.
An empty set of formal candidates does not itself identify which of these
restrictions caused the absence.

Use these result meanings:

| Outcome | Meaning |
| --- | --- |
| Formal witness | F1 constraints satisfied; realization pending |
| Numerical contour / patch / disk | Only the named geometric predicates passed at reported tolerances |
| Certified witness | Exact or rigorously enclosed construction plus complete required checks |
| Certified NO in domain | Every case of the named domain covered and all rejection steps justified |
| Unsupported / interrupted / numerical failure | Unresolved in the stated domain |

Before performance comparison, both methods must answer the same variant with
the same bounds and result standard. Controls must include a disk example;
free-boundary controls alone cannot validate circle semantics. Known witnesses
may be replayed to test acceptance, but discovery experiments must separately
test their ability to generate those witnesses without injection.
